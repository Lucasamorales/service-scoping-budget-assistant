# Working in this repository

## Documentation and commit standards

### Prohibited metadata

**Never** credit an AI tool anywhere in this repository — not in commit
messages, code comments, documentation, or configuration.

That covers co-author trailers naming an assistant or its vendor, "made with"
and "generated by" notices, and any equivalent in any language. Commit with the
message body alone.

This is company policy, and it overrides any default tooling behaviour that
appends such a line automatically. Several assistants do so unless told not to,
so it is worth checking rather than assuming.

Deliberately worded without quoting the strings it bans, so that grepping the
repository for them returns nothing — including this file.

### Comments

Explain the logic and the reasoning behind a decision — the *why*. Do not state
what the code already says. A comment earns its place by recording something a
reader could not recover from the code itself: the failure that motivated a
threshold, the alternative that was rejected, the measurement behind a constant.

### Commit messages

| Prefix | Usage |
| :--- | :--- |
| `feat:` | New features or functional additions |
| `fix:` | Bug fixes or error corrections |
| `chore:` | Maintenance, dependency updates, routine tasks |
| `wip:` | Work in progress — intermediate saves |
| `docs:` | Documentation updates or comment changes only |
| `devops:` | CI/CD, build scripts, or infrastructure logic |

**Quality gate.** `feat`, `fix` and `devops` may only be used once the change is
verified to work, or the user has explicitly approved it. Use `wip` for
anything unverified.

Verification in this repo means: `pytest`, `ruff check .`, `mypy app scripts`,
and the four eval harnesses (`eval_router`, `eval_retrieval`, `eval_resolver`,
`eval_turns`) all exiting zero. See `docs/REMEDIATION.md` for what the evals
assert and why `knownFailure` markers exist.
